# Code of Conduct

## Our Commitment

We are committed to providing a welcoming, respectful, professional, and inclusive environment for everyone participating in the Enterprise Operations Platform project.

We value constructive collaboration, technical excellence, open communication, and respect for different perspectives and experiences.

All contributors, maintainers, reviewers, users, and community members are expected to follow this Code of Conduct.

---

## Expected Behavior

Participants are expected to:

- Treat everyone with respect and professionalism.
- Communicate clearly, constructively, and in good faith.
- Welcome different technical perspectives and approaches.
- Provide constructive feedback focused on the work rather than the individual.
- Accept reasonable criticism and feedback professionally.
- Collaborate toward solving technical and product problems.
- Respect project decisions and documented processes.
- Protect confidential and sensitive information.
- Follow the project's security and responsible disclosure practices.
- Help maintain a safe, productive, and inclusive community.

---

## Unacceptable Behavior

The following behavior is not acceptable:

- Harassment, intimidation, or bullying.
- Discrimination based on personal characteristics or identity.
- Personal attacks, insults, or deliberately hostile behavior.
- Threats of violence or intimidation.
- Sexual harassment or inappropriate sexual conduct.
- Publishing or sharing another person's private information without permission.
- Deliberate disruption of project discussions, reviews, or development activities.
- Trolling, baiting, or repeated bad-faith arguments.
- Impersonating another contributor, maintainer, or project representative.
- Introducing malicious code or intentionally compromising project security.
- Attempting to access systems, accounts, data, or credentials without authorization.
- Publicly disclosing security vulnerabilities before following the project's security reporting process.

---

## Technical Discussions

Technical disagreements are expected in software development.

When disagreements occur:

1. Focus on requirements, evidence, architecture, and technical trade-offs.
2. Explain your reasoning clearly.
3. Avoid personal criticism.
4. Consider alternative approaches objectively.
5. Respect the final decision made through the project's established review process.

Disagreement with an implementation or architectural decision does not justify disrespectful behavior.

---

## Security and Privacy

Contributors must take security and privacy seriously.

Do not:

- Commit passwords, API keys, tokens, or private keys.
- Publish private user information.
- Attempt unauthorized access to project infrastructure.
- Exploit vulnerabilities for personal gain.
- Intentionally introduce malicious or destructive code.

Security vulnerabilities must be reported according to [`SECURITY.md`](SECURITY.md).

---

## Reporting Unacceptable Behavior

If you experience or witness behavior that violates this Code of Conduct, report it privately to the project maintainers.

When possible, include:

- A description of the incident.
- Date and approximate time.
- Relevant repository, issue, pull request, or discussion.
- Names or usernames of involved participants.
- Supporting information or evidence.
- Any relevant context.

Please avoid publicly escalating sensitive incidents when private reporting is appropriate.

---

## Handling Reports

Project maintainers will review reports as promptly and fairly as reasonably possible.

Depending on the circumstances, maintainers may:

- Request additional information.
- Speak privately with involved participants.
- Remove inappropriate content.
- Issue a warning.
- Temporarily restrict participation.
- Remove participation privileges.
- Take other appropriate action consistent with project policies.

Reports will be handled with appropriate discretion.

---

## False or Malicious Reports

Reports made in good faith are welcome, even when an investigation does not ultimately determine that a violation occurred.

Knowingly submitting false reports, fabricating evidence, or intentionally abusing the reporting process is not acceptable.

---

## Scope

This Code of Conduct applies to project-related activities, including:

- GitHub repositories
- Issues
- Pull requests
- Discussions
- Code reviews
- Documentation
- Community channels
- Project meetings
- Events organized by the project
- Other spaces where participants are representing or substantially participating in the project

---

## Maintainer Responsibilities

Project maintainers are responsible for:

- Maintaining a professional development environment.
- Applying project policies consistently.
- Reviewing reported incidents appropriately.
- Protecting sensitive information involved in reports.
- Taking reasonable action when violations occur.
- Communicating relevant project decisions clearly.

Maintainers are also expected to follow this Code of Conduct.

---

## Professional Collaboration

Contributors are encouraged to assume good intent while remaining attentive to the impact of their actions.

Good collaboration includes:

- Asking questions before making assumptions.
- Explaining technical decisions.
- Giving actionable feedback.
- Recognizing mistakes and correcting them.
- Giving credit to contributors.
- Sharing knowledge with the team.
- Keeping discussions focused on solving problems.

---

## Attribution

This Code of Conduct is inspired by established open-source community standards, including the Contributor Covenant.

The project may adapt these guidelines as its community and governance requirements evolve.

---

## Updates

This Code of Conduct may be updated as the project develops.

Significant changes will be documented through the project's normal repository and release processes.

---

## Contact

For conduct-related concerns, contact the project maintainers through the private communication channel specified in the repository.

For security vulnerabilities, **do not use the public issue tracker**. Follow the instructions in [`SECURITY.md`](SECURITY.md).
